# 内容表达与页面设计

## 使用范围与来源

阶段3阅读“内容与逐页方案”，阶段4阅读“视觉规范与代表页”，阶段7阅读“表达质量复核”。这些是人工设计和验收标准，现有程序只核对基础字段、文件和状态，不能自动判定页面是否有说服力或有“AI味”。

方法参考宝玉 `baoyu-slide-deck`，以下为适配后的自编规则，未安装上游技能、未复制制作代码。核对日期：2026-11-05。

上游面向阅读分享的图片式幻灯片。本工作流同时支持现场汇报，默认可编辑：借鉴设计方法，文字、表格和可重建的数据图使用原生对象；科学结果用真实来源图，不用生成图片冒充结果。不继承固定封底、禁页码、手绘风、强制行动号召或整页图片等与任务无关的规定。

以下科研组织方法可独立使用。培训及工程场景见 [培训与工程表达](training-engineering-design.md)。公开版只包含通用方法，不包含私人参考演示稿及其素材。

## 内容与逐页方案（阶段3）

### 先组织论证

从 `brief.md` 核对用途是现场讲解、独立阅读还是兼用，以及听众需要理解什么。现场页保留讲解所需的证据、单位和关键条件，推导细节可放备注；独立阅读页应能自洽。用途尚不明确时结合会话判断，影响内容量时再询问。

按听众需要重组材料，重点分析仍遵守原有确认顺序。用户要求章节结构时，在逐页方案前展示“章节—本章问题—主要证据—篇幅分配”；简单短稿可直接安排页面，不强设章节数、目录或分隔页。章节信息保存在大纲中，不额外创建章节文件。

按内容选择推理顺序，例如“问题—方法—结果—解释”或“论点—证据—意义”。相邻页面应能解释为什么接着讲下一页。页数服从任务约定；需要增减时走需求变更，不靠堆目录、空转场或总结凑页数。

### 每页分开记录四个决定

在现有 `outline.json` 中保留所有原字段，并按本轮设计填写下表。新增字段可由现有程序原样保存，但不在它的强制检查范围内，须人工验收。

| 字段 | 实际要写的内容 |
|---|---|
| `chapter` | 有章节时写所属章节；无章节时可省略 |
| `purpose` | 本页在整场汇报中的作用，不只是重复标题 |
| `message` | 听众应理解的一件主要事情；方法页可以是需要理解的关系或步骤 |
| `title`、`content` | 最终标题与必要文字，避免用泛泛口号代替具体内容 |
| `evidence` | 稳定来源ID及页码、图号、数据列或条件，沿用原来源规则 |
| `visual_priority` | `must` / `support` / `text`，说明可视化对本页是否必要 |
| `visual` | 呈现形式、具体来源图/数据、需要强调的比较或局部；纯文字页说明为何足够 |
| `layout` | 主体、辅助说明和阅读顺序；位置或比例应足以指导制作，不能只写“美观清晰” |
| `speaker_notes` | 口头解释、推导、备用问答及来源，不重复整页文字作为填充 |

`message` 是一个焦点，并不限制一页只能有一项数据。所有结论须保留适用条件；数据来源在页面上以简短来源标记可定位，完整出处放备注。结构页可不带事实证据。

### 先决定表达形式，再选空间布局

| 要讲的内容 | 优先考虑的表达 | 布局判断 |
|---|---|---|
| 趋势、频响、局部峰谷 | 真实曲线与必要标注 | 让曲线占主要区域，文字贴近相关区段，保留范围、坐标和图例 |
| 机制、结构、输入与输出 | 有标签的示意图或真实模型图 | 根据关系安排方向和层级；简单关系可用文字，无需装饰图 |
| 前后或方案对比 | 相同口径的并排图、叠加曲线或差值图 | 统一坐标和条件，解释比较对象，避免误导性缩轴或裁切 |
| 操作或筛选过程 | 流程、顺序展开或简洁步骤 | 顺序与分支应有实际含义，步骤很短时可只用文字 |
| 多维条件、精确设置 | 表格 | 行列确有比较职责才用表，不把所有段落转成表格 |
| 单项关键发现 | 关键数值配必要上下文，或证据图加结论 | 用哪个为视觉主体取决于听众需要理解数字还是形成原因 |

整稿扫描重复布局是否妨碍理解。可复用网格和字体层级，各页仍应根据内容分配视觉权重；不设固定图表数、表格数或版式轮换配额。

### 复杂研究内容：总览、展开与对应

用于有多条理论、多个研究任务或较多技术细节的开题、答辩及组会。内容量应满足听众理解方法与证据的需要，并通过清楚的组织维持可读性；不将其变成所有演示文稿的密度默认值。

可复用的组织判断：

| 内容任务 | 组织方式 | 设计判断 |
|---|---|---|
| 研究现状 | 时间线、方法分类及所选方向 | 建立问题领域的地图，说明本研究所在分支和选择依据 |
| 研究目标与内容 | 目标分项，与模型、分析和方法对应 | 每项任务交代对象、问题、方法与评价输出 |
| 多任务方法 | 总览后按相同任务逐项展开 | 名称、编号与后续细节保持一致 |
| 技术路线 | 阶段依赖与输入输出 | 说明每个理论计算什么、条件是什么、输出交给哪一步 |
| 分析与架构 | 按语义分区，图文就近对应 | 减少读者在图、公式和说明之间寻找配对的负担 |

阶段3先做以下内容设计，直接写进已有 `content`、`visual` 与 `layout`：

1. **明确每个内容块的职责。** 可采用“研究任务、理论依据、处理过程、证据、解释”等分区，不按字数机械分成三个方框。每个块都要服务本页的主要问题。
2. **建立跨页的对应关系。** 多任务研究可以先总览，再分项；总览不必塞下每个公式。后页沿用同一任务名，并具体展开总览留下的问题。短稿若一页足以说明关系，无需额外加总览页。
3. **把必要的技术内容留在页面上。** 方法、关键假设、核心公式、参数施加位置、输入输出及结果解释，按听众需要呈现。备注补充推导和问答，不应成为理解主方法的唯一入口；结果页也要留足条件和解释，不能只放曲线及一句赞语。
4. **按依赖关系组织图形。** 时间先后用顺序，分类用分支，模块配合用结构，前后处理用输入输出。箭头、括号、分组和对应颜色须有实际含义；实现方式遵循当前制作技能，不凭装饰需求增加复杂图形。
5. **检查任务与产出是否配对。** 每项分析说清将生成/已得到什么图或指标、用它回答什么问题。有结果时用真实证据；仅有计划时写预期输出并保持相同标识，不能用示例图暗示完成。

例如，座舱驱动方法页可按现有来源组织为：固定中低音及可调高音支路的输入；增益/延时/极性作用位置和线性叠加关系；四座位采样及极差计算；输出约束与COMSOL复算。详细页再解释参数取值、逐频曲线与误差。这个组织保留步骤之间的关系，具体数据仍须来自本任务，不能借参考稿补出未做的研究。

“一页一个主要意思”允许多个相互依赖的内容块共同回答一个问题。若图文已经无法在实际观看尺度下辨认，先移除重复信息、拆分过长论证或重新分配页数，再压缩字号；若页面只有大标题、大数字和宽阔空白，则检查是否遗漏了本来需要展开的方法或解释。

### 去除模板化表达

删除无信息的引导、夸张和收尾，如“让我们深入探索”“革命性突破”“综上所述”后的机械重复。保留有实际语义的普通用词，不用禁词替换制造新套话。

结果标题尽量写清对象、变化与条件；方法和背景页可用明确主题名。用具体事实替换“显著提升”“全面优化”等无证据判断，不把每个标题写成商业口号。结束页回到结论、未决问题或下一步，按场景保留感谢/问答，不强塞行动号召。

示例：讲“驱动方案的收益”时，既可用汇总图交代幅度，也可用优化前后曲线解释变化来自哪里。选择依据是本页问题；不能因为汇总图容易制作而省掉本来需要解释的频率结构。此例不要求所有技术报告都放频响图。

## 视觉规范与代表页（阶段4）

在现有 `visual.md` 集中记录下列规则，后续页面从这里读取，不逐页重新猜风格。用户模板优先；以下维度用于分析模板或自由设计，不要求重新设计已有模板。

| 职责 | 决策与记录 |
|---|---|
| 质感 Texture | 纯净、网格、纸张等背景处理及必要程度；装饰不得掩盖证据 |
| 色彩 Mood | 背景、主要文字、次要文字、强调色的色值与用途；同时记录图表类别/方案的颜色映射 |
| 排印 Typography | 标题、正文、图注、数据标签的实际字体、字号、字重和行距；核对字体可用及中英数字支持 |
| 密度 Density | 根据用途、听众和页面类型确定内容量；允许技术页较密，封面和结论较疏，不强求全稿一样稀疏 |
| 结构 Layout | 画布、页边距、对齐网格、图文比例与适用的页面类型；具体页面安排仍来自逐页大纲 |

复杂内容页可建立“章节—当前任务—块标题—具体说明/图注”的层级。共用标题带或网格使位置稳定，内部区域随语义变化；相关块用对齐、相邻位置和一致编号表达配对。边界、底色、连线在帮助分组时使用，不把特定参考稿的阴影、虚线框、竖排字或蓝红配色设为必选装饰。密度适配技术讨论，不以减少字数、减少表格或增加留白本身作为质量目标。

颜色按含义复用：同一座位、方案或变量在相关图中尽量保持同色；图例、线型和标签也应能区分类别。强调色用于引导注意，不能单靠颜色传达差异。无需把“收益/代价”永久绑定为特定颜色。

字体先定义层级再确定具体字体。技术内容应重视数字、单位、符号和细标签的辨识；“技术风”不等于把所有中文改成等宽字体。图片生成时描述字形；原生PPT必须记录和设置实际字体。字号与比例以最终观看尺度的可读性为准，不机械套标题/正文倍数。

代表页按风险选择：需要验证图表解读就选真实结果页，需要验证结构关系就选方法页，需要模板匹配就选典型页面。数量由覆盖风险决定，不固定三页。展示时说明视觉主体和阅读顺序，确认信息层级、证据可读性及风格后再扩展。已有明确授权可继续，不重复索要同一决定。

## 表达质量复核（阶段7）

在 `qa.md` 记录具体观察和修正，并将依据写入现有检查项；不新增一组形式化“去AI味评分”。

- `facts`：关键证据是否支持标题，统计口径、范围、单位和限制是否仍可见；来源是否可定位。
- `visual`：逐页实际观看，先看到了什么，是否符合 `message`；图的标注是否解释发现；是否有被巨型标题挤小的关键图、无意义留白或重复表格；章节间是否形成合理阅读节奏。
- 复杂研究内容另核对：总览与展开的任务是否一一对应；依赖关系、必要公式及输入输出能否在页面上理解；图与解释能否就近配对；预期与已完成是否明确；分区是否帮助阅读且小图标签仍可辨。将发现写入同一份 `qa.md` 和现有 `story` / `evidence` / `visual` 检查依据，无须新增表单。
- `structure` / `editability` / `export_review`：继续执行原结构和最终导出检查，不能用它们替代表达质量复核。

发现标题概括过度、证据表达薄弱或布局不合适时，回到对应的内容/视觉阶段修订，并按原流程使相关检查失效。设计修改后再查完整导出，不能只读代码或检查预览文件是否存在。没有发现问题时也应给出具体观察依据，避免只写“专业、美观、无AI味”。

这种方法提高设计决策的具体程度，不保证生成结果自动优秀。最终稿仍须经实际查看与用户反馈检验。
