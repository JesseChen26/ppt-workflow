# 培训与工程表达

适用于培训课件、软件操作说明、参数比较和工程改善汇报。以下为通用设计方法，具体技术结论、案例与素材须由本次任务提供。科研开题同时参考 [内容表达与页面设计](design-method.md)。

## 按听众要完成的事组织内容

在已有 `objective` 和 `brief.md` 中明确目标：理解概念、照做操作、比较方案或作出工程决定。目标尽量写成可观察动作，如“完成设置并识别正确输出”。

| 用途 | 可选讲解顺序 |
|---|---|
| 新概念或理论 | 现象或实物 → 简化模型 → 公式与符号 → 应用 |
| 参数影响 | 变量与固定条件 → 同口径比较 → 变化区段与设计含义 |
| 工程改善 | 问题与判据 → 候选原因 → 分析与排除 → 改动 → 验证及残留问题 |
| 软件操作 | 前提与输入 → 步骤与界面 → 关键设置 → 检查输出 → 常见错误 |
| 工艺与检验 | 物料或部件 → 加工装配 → 中间产物 → 检验判据 |
| 培训迁移 | 知识说明 → 案例 → 学员任务 → 反馈 |

依据听众、时长与材料选用，不规定固定页面配额。没有来源的例题答案、阈值和工程建议应单独验证。

## 让页面承担具体任务

- **保持定位稳定。** 章节、标题与页码位置稳定，正文按内容采用单图、双图、图文、流程或表格。不同画布比例应重新排版。
- **保留技术细节。** 给对象、证据和解释分配空间。技术页可以较密，但不能同时保留无意义的大片空白并将关键图缩至难辨。
- **连接机制与响应。** 说明改变了哪个参数、作用于何处、产生何种响应；图与说明相邻，标注不遮挡证据。
- **统一比较口径。** 区分固定电压、固定功率等条件；共享横轴的图可以对齐，不同指标保留各自单位。同一指标跨方案使用一致坐标。
- **用局部标记解释证据。** 指出读哪里、变了什么、意味着什么。阈值与经验结论须保留来源和适用范围。
- **让流程符合实际。** 顺序、并行和合流应有真实含义。普通步骤与判断分支使用不同职责的节点。
- **区分操作和结果。** 操作截图保留界面定位信息，并放大关键控件；研究结果页优先呈现数据图或模型输出。
- **按用途选表格。** 分类和精确查值适合表格，趋势适合曲线，缺陷比较适合同尺度图片。大表可逐步展开，完整数据放附件。

## 阶段7复核

沿用 `story/evidence/visual/facts/export_review` 和 `qa.md`，检查：

1. 标题、图例、单位与正文是否指向同一对象；中英文标签与图形是否一致。
2. 公式、下标、单位和箭头是否被裁切；截图高亮是否与说明一致。
3. 现场讲解页是否可读；查阅材料是否需要另附讲义。
4. 嵌入表格、视频或附件是否存在静态摘要；未实际打开的附件不得声明已验证。
5. 前后对比是否同口径；假设、排除过程与验证是否分开；样本量与未解决问题是否保留。
6. 操作能否照做，练习是否对应目标，反馈是否有依据。静态页面检查不能证明培训有效。

## 落实到已有记录

内容写入 `outline.json` 的 `purpose/content/evidence/visual/layout/speaker_notes`；视觉规范写入 `visual.md`；具体问题和修正写入 `qa.md`。不额外增加状态字段、审核节点或覆盖默认值。最终仍需实际查看页面，并根据目标听众的使用反馈修订。
